Catches the pull request description that is the diff written out in prose: the file-by-file walk, the bullet list of moves, and the `## Why` heading filled with the what. It also catches the two ways a description pretends to have answered: the purpose sentence that survives having its `so that` removed because it restates the change, and the bare ticket reference standing where the reason should be, which names where the reason is kept rather than giving it. What a reader cannot get from the diff is a failure, a cost, a limit, a constraint or a decision taken elsewhere, and one sentence of it is enough; the regex-grade neighbour is the empty template, a body that is still the headings the tool inserted, which a `grep -c` on the heading text answers without a model.
